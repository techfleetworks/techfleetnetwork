# Frontend universal requirements re-audit (2026-10-30)

Dimension: accessibility (WCAG 2.2 AA, AAA where feasible), browser and device support, usability and universal design.
Repo: `tfn-reaudit` at `e4c366190af4aa6765ff55b82fbd7920509aa86d` (origin/main, 2026-10-17).
Method: static read of config, CI workflows, GitHub API (rulesets + run history), exhaustive greps over `src/**/*.tsx`, and a deep read of 16 key flows.
No prior baseline for this dimension. Nothing in the app was run. Every runtime claim (rendered contrast, screen reader output, real focus order, real browser behavior) is **not-assessed** unless stated.

## Scores

| Sub-score | Score | Band |
|---|---|---|
| Accessibility (WCAG 2.2 AA) | **55 / 100** | Weak (40-59) |
| Browser and device support | **48 / 100** | Weak (40-59) |
| Usability and universal design | **63 / 100** | Adequate, material risk (60-74) |

Why. The building blocks are good and clearly made by people who care: skip links on every layout, per-route `document.title`, a route-change live announcer, a global `:focus-visible` ring, a global reduced-motion guard, every dialog titled, every icon-size button named, every `<img>` carrying `alt`, a DS `Field` that wires `aria-describedby`, an axe + keyboard-walk Playwright suite, a 14-profile device matrix, and `browserslist` + `eslint-plugin-compat`. The problem is that **none of the runtime checks run**, and the static checks are warn-only. So nothing stops a regression, and the code already has Level A and AA failures that a running gate would have caught. The public accessibility policy also claims full WCAG 2.2 AA conformance, which the code does not support.

## Limitations

- No `node_modules`: could not run ESLint, Vitest, Playwright, axe or Lighthouse. Current jsx-a11y and compat warning counts are **not-assessed**.
- Every contrast number is computed from CSS tokens, not from rendered pixels. Overlays, opacity and parent backgrounds can change real values.
- Screen reader, zoom/reflow at 320px, real focus order, real touch behavior, and real Safari/Firefox rendering are all **not-assessed**. These need the e2e lanes to run (A11Y-1, BRW-1) plus a manual pass with NVDA/VoiceOver.
- The e2e skip root cause is inferred from GitHub's job-skip semantics, not reproduced.
- Grep heuristics have false negatives (G1b proved this); G1 used a better scan but still bounded to 15 lines.
- Usability score is expert-heuristic only; no user testing data exists in the repo.
