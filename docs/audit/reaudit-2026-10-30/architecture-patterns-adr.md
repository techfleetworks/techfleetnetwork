## Limitations (the biggest first)

1. **Static only.** No load test, profiling, or runtime contract probe. Scalability (ARCH-8) and the impact side of ARCH-1 and ARCH-3 are inferred.
2. Pattern judgments (god object, three homes) come from reading code and counting lines, not from coupling or cohesion metrics (no dependency-cruiser run). A fresh-context `judge-arch` second look is the upgrade path.
3. ADR quality was checked by heading regex across all 86 plus about 8 reads. Whether alternatives were *genuinely* considered was not judged for each one.
4. The raw-fetch timeout heuristic can miscount in either direction. I did not trace each call's host.
5. Infra (Supabase pooler, instance size, Cloudflare git integration state, platform wall-clock limits) and external SLO tooling are not visible from the repo.
